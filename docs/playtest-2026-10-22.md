# Local playtest — 2026-10-22

Stack: `docker compose up --build -d` from this worktree (fork/main `b519acb`), browser pane at
`http://localhost:11400`, logged in as the seeded `modern_player`. Desktop at 1280×900 and the
375×812 phone preset. Both maps were played: World War I Era (Game 28, training, no fog) and
Battle of the Elements (Game 29, training, fog of war, 1-minute turns).

## What works

- Register / log on / log off / lost-password pages, home dashboard, player info, messages,
  contact, settings (password change), game manual, admin stats, IP history, tournament
  bracket with join/quit.
- Full turn loop on both maps: place → attack → transfer → End Turn → resolution, with the
  Computer taking random turns. The turn scheduler auto-ran a 1-minute game with no clicks.
- Fog of war hides territories and the results feed still names captures.
- Replay stepper highlights each event in the results list; lenses (Owner / Region control /
  Frontier) switch; region-bonus legend updates ("Twin Bridges held +3").
- Quit ends a two-player game and the game-over card shows placement; "Play again" and
  "Back to Home" work. Finished games appear under All Games.
- Phone layout: full-bleed map, HUD pills, floating End Turn, drawer for players/chat.

## Bugs found (ordered by impact)

1. **Elements map adjacency is asymmetric.** `engine/map_info.ex:80` lists Carbon
   Oxidization as `[9, 11, 12, 9]` (Flame twice) while Steam (`7`) lists Carbon Oxidization.
   Steam can attack Carbon Oxidization but not the reverse. Inherited verbatim from
   `GlobalCombat.Core/MapInfo.cs:183`, so either the original had this bug for 20 years or the
   second `9` was meant to be `7`. Worth a decision and a test.
2. **Quick-amount race assigns the wrong number.** *(fixed 2026-10-23: picks mirror into the inputs client-side)* `1 · Half · Max` are server events; the
   number input is only updated when the diff comes back. Clicking Half and then Assign
   quickly submitted 28 instead of 14 (logged: `change_amount 14` then `submit_order 28`).
   Under any latency a player can place or attack with a stale amount. Fix: update the input
   client-side in the hook, or disable the submit until the diff lands.
3. **Quit has no confirmation.** *(fixed 2026-10-23: two-tap arming, same as End Turn)* `dock.ex:135` and `lobby.ex:50` fire `quit` on a single
   click; it forfeits the game immediately and cannot be undone. Needs a confirm step (the
   End-Turn "tap again" arming pattern already exists and fits).
4. **No turn clock anywhere.** Games have a turn length (1 min to 3 days) and the scheduler
   forces turns on it, but the HUD, lobby and home list never show when the next turn runs.
   Game 29 ran eight turns on its own while I read code. Show "Turn runs in 42s / at 14:05"
   in the status bar and on the home game list.
5. **Chat input is not cleared after Send** *(fixed 2026-10-23: form resets on submit)*, so a second press re-sends the same text (the
   log shows two identical `send_chat` events). Reset the form on submit.
6. **Create Game form submit stalls when the LiveView socket is reconnecting.** The button
   goes into `phx-submit-loading` and stays grey with no feedback ("push timeout" in the
   console). Partly an environment issue (host was overloaded), but the page should surface
   a disconnected banner and re-enable the button.
7. **Console error at game mount:** `Multiple IDs detected: game-drawer` (LiveView dev
   check). Likely the drawer is rendered twice during the dead/connected render.
8. **Region control and Frontier lenses look identical** when no region is held: both paint
   the whole board grey. Frontier should still outline contested borders.
9. **Create Tournament defaults `Option Game Id` to 700460**, a legacy production id that
   does not exist in this database. Game Size offers "42".

## Per-game critique

### World War I Era (original map)

- Readable and faithful. Army badges are legible at desktop width; order arrows are drawn
  but are thin and low-contrast on blue territories — easy to miss that an order exists.
- The right column stacks players → Your armies → Your orders → Turn results → chat in one
  scroll. At 1280×900 the player list (who is Done) scrolls out of view as soon as results
  are open. Pin the player status row, or collapse results by default.
- "Your orders" lists orders as text but offers no remove button; you must find the arrow on
  the map. Add a remove/edit control in the list.
- The Computer attacks with 1 army, transfers in circles, and places everything on one
  territory. Training Mode is fine for learning the controls but does not teach strategy.
  Even a greedy heuristic (reinforce frontier, attack when 2:1) would make it a real warm-up.
- Turn-results toast never auto-dismisses; results list also does not scroll to the newest
  turn.
- Legacy manual says "click the number of armies" and shows old dialog screenshots; the
  current UI is click-territory-then-panel. The manual needs new screenshots and wording.

### Battle of the Elements

- The diamond board does not fit the panel on first load; the bonus legend is clipped until
  you press Fit. Fit should be the default for this map.
- Water territories use a blue wave texture that reads as the blue player at a glance; Earth
  uses green like the green player. Either shift the element textures to neutral hues or let
  player colors be chosen from a palette that avoids the element colors.
- Under fog, hidden tiles are drawn as plain grey diamonds with no name; the accessible table
  says "hidden by fog of war" but the map gives no hover hint. A dashed outline + name would
  help planning.
- The corner/bridge bonuses are the whole strategy here, but the legend only shows values.
  Highlighting a region's tiles on legend hover would make the map teach itself.
- Name data has typos inherited from the original ("Carbon Oxidization").

### Lobby (Game 22, Game 29)

- A full lobby (2/2) shows no Start button to non-creators and no hint about who can start
  or whether it auto-starts. Show "Waiting for <creator> to start" and the game settings
  (map, fog, turn length, min armies) — none of these are visible once you leave the form.
- Training games still require the creator to press Start; auto-start would remove a click.
- Player pills say "Thinking" while waiting in a lobby; the label only makes sense in play.

### Tournaments

- `/Tournament-:id` and `/Create-Tournament` render without the site chrome in a light
  theme, same as `/account/settings` — three pages look like a different product.
- Join, Quit, START TOURNEY and KILL TOURNEY are GET links. Join/Quit are state-changing and
  Kill is destructive; they should be POST forms with confirmation.
- "Join This Tournament" appears twice on the page.

## Site-wide suggestions

- Add an admin section to the nav for admins (Stats, IP history, Create Tournament are
  reachable only by typing the URL; non-admins are silently redirected home with no flash).
- `/design` smoke page is reachable in dev routing; gate it or remove.
- Home "Your Current Games" cannot be sorted or filtered and does not say whose turn it is or
  when the next turn runs; a "needs your orders" badge would be the single most useful thing.
- Settings only changes the password; there is no email change or opt-out toggle in-app.
- Stats line chart connects three logins across 20 days as one line; use bars per day.
- Phone: the "..." map menu does not close on Escape or outside tap, and territories are
  tiny at default zoom (badges ~20px). Default to a fitted zoom on your largest cluster.

## Environment notes

- The host was under a load average near 1000 from unrelated builds, so first page loads
  took 4–24 s on the host side (the container answered in ~0.5 s). The Phoenix code reloader
  adds ~1.5 s per request on the bind mount. LiveView fell back to long-poll several times.
- `mix deps.get` in the dev container failed once on Hex registry timeouts ("Unknown package
  expo in lockfile"); a second `docker compose up -d web` succeeded.
- Dev DB was left as found except: Game 29 (finished training game) exists; the QA Cup
  tournament and the temporary admin flag on `modern_player` were removed.
