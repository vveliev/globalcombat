## New findings (ordered by impact)

1. **`games.turn` runs three ahead of the engine in Game 30.** Board and player list say
   Turn 4, the feed says "Turn 3 results", `games.turn` = 7. A timed check across the 03:47:49
   claim showed each claim now runs exactly one engine turn (board 3 → 4, column 6 → 7), so the
   offset came from the first three claims after Start (03:22–03:32), which bumped the column
   (`Scheduling.claim_turn/2` does `turn + 1` unconditionally) without the engine advancing —
   no resolver error was logged. Games 24/28/29 are consistent. Worth a test that claims N times
   against a live Server and asserts the column equals the engine turn, or let the engine own
   `turn` and have `claim_turn` touch only the timestamps.
2. **Automatic turn runs are silent, and Force Turn is a silent no-op.** The scheduler forced
   Game 30 while I was mid-turn with nothing in the results feed or chat saying so (only a
   player-forced run posts "X forced the turn to run."). Force Turn is always enabled but
   `handle_cast({:force_turn, …})` ignores it until `time_left <= 0`, with no feedback. Disable
   it until the deadline, label it "Force Turn in 3:12", and post a system line when the
   scheduler runs a turn.
3. **Turns 2 and 3 of Game 30 recorded no Computer orders at all** — only the two income
   lines each. Turn 1 (orders queued in memory by `do_start/1 … run_ai_turns`) had placements,
   transfers and attacks. `run_turn/2` does call `run_ai_turns/1` after every resolution, but
   the wire snapshot (`Engine.Wire`) carries `assigned_armies` and not attack/transfer orders,
   so a Server rehydrated from the snapshot, or a turn resolved offline by `LiveResolver`,
   resolves with the Computer's queued orders gone (the moduledoc on `run_ai_turns/1` warns of
   exactly this). Unverified which path Game 30 took; the empty turns are the symptom.
4. **Finished training games look like real games.** Player Info lists Games 27 and 29 as
   "Finished" while Wins/Total Games/Rating stay 0/0/8500, because training results are never
   recorded (`record_game_results/2` skips `is_training`). Label them "Training · unrated".
5. **"Games to Join" lists full lobbies and games you are already in.** Game 22 (2/2, I'm
   seated) shows under Games to Join on Home and in the logged-out view. `list_new_games/0`
   filters only on status/private.
6. **Training Mode doesn't disable Max Players.** The select stays live; `create` silently
   forces 2.
7. **Create Tournament stores 700460 when Option Game Id is blank.** I cleared the field; the
   INSERT still carried 700460 (schema default wins over the empty string).
8. **Legacy and error routes return bare text.** a legacy `/Game-<id>/Index` URL → "Game 28 action=Index"
   (stub `GameController.show/2`); `/Tournament-1` and `/Player-Info-999` → "Not Found" with no
   layout; an unknown game id redirects Home and the "Game not found." flash is not visible there.
9. **Game over keeps fog on.** Game 29's final board still hides 10 territories from the loser;
   the eliminated row has no army/territory totals; "Defeat" is printed three times (pill,
   heading, card).
10. **Spectating is unmarked.** Game 24 (not seated) shows the full board, players and a live
    chat box with nothing saying "Spectating"; logged-out visitors get a fully fogged board.
11. **Accessibility names.** The three header theme buttons have no label; the player pill
    "91 (15)" has no label for armies vs territories; fogged tiles have no `<title>` or name on
    the map (only in the table).
12. **Submit label trails the picked amount.** After ½ the input said 7 but the button said
    "Assign 15" for ~700 ms. Harmless now that the input is authoritative, but confusing.
13. **Log On takes ~9 s** (`Sent 302 in 8966ms`; PBKDF2 plus the dev reloader) with no pending
    state on the button, so a second click is tempting.
14. **Duplicate headings** on Messages, Email Opt Out and IP Address Login History (page
    title + card header are the same string).
15. **`UserAuth` moduledoc claims the session cookie carries `:max_age`;** the endpoint's
    `@session_options` set none, so it is a browser-session cookie. Doc or code should change.
16. **Home shows Game #30 as "Turn 4" while its board said "Turn 2"** at the same moment —
    the visible symptom of finding 1.

## Per-game critique

### World War I Era (Game 28)

What works: place → attack → transfer → End Turn → resolution all land; the "Replaces X's
order" warning fires on a second order from the same source; the End Turn ring fills as armies
are placed; results are specific ("Tanzania attacked South Africa with 24 armies: 4 lost, 7
defenders lost, South Africa captured"); income breakdown card is clear.

- The dock closes after every Assign, so placing on several territories is click → ½ → Assign →
  click → … A sticky "placement mode" (panel stays open, next click re-targets) would halve the
  clicks; the phone's placement bar already works that way.
- Results are a flat list in resolution order. Group by player, colour the owner swatch, and put
  the viewer's own lines first; link each line to the territory (the replay stepper already
  knows the mapping).
- "Alaska received 7 armies" reads like a transfer; say "placed".
- Army badges are 10 px text on desktop and 11 px territories exist on the phone preset — tiny.
- The Computer ends its turn instantly, so a 1-day game against it never waits; in training
  show "Computer is ready" rather than "Done" and run the turn on your End Turn (it already
  does — say so in the coach line).
- Players list pill "112 (15)" needs a legend or two labelled numbers.

### Battle of the Elements (Games 30, 29, 24)

- Fit should be the default on desktop: at 1280×900 the board column is 634×696, so `home()`
  zooms to the viewer's cluster and the Water corner is off-screen.
- Fog at start hides only the two long bridges (Water to Fire, Wind to Earth); the strategic
  value of fog here is low until mid-game. Consider starting with corners hidden.
- Fogged tiles are plain diamonds without a name; the table says "hidden by fog of war" but
  the map gives no hover target. Dashed outline + name.
- The legend lists bonuses (Four Corners +7, Fire +5, …) but never highlights which tiles make a
  region; hovering a legend row should light its tiles.
- Spectator/logged-out view of a fogged game is entirely hidden — fine, but say so instead of
  drawing 38 blank tiles.
- Adjacency bug (Carbon Oxidization) still shipped; add a symmetry test over `@elements_areas`.
- Random start is uneven for the corners: I held Fire Corner, Earth Corner and Smoke Bridge
  from turn 1 (three of the seven Four Corners tiles); the rule that "no one starts with an
  entire region" does not cap partial corner sets.

### Training AI (both maps)

- `RandomAi` places 10 armies at a time on random owned areas, attacks with everything from
  random areas and transfers in circles. In Game 24 the Computer holds 35 of 38 tiles with 304
  armies by turn 13 against an idle human; in Game 28 it attacks with 1 army. It teaches the
  controls, not the game. A small greedy policy (reinforce frontier tiles, attack at ≥2:1, never
  transfer away from a frontier) would make Training Mode a real warm-up without touching the
  oracle-locked `think/1`.
- The AI's "Done" pill is instant; the human cannot tell whether the turn will run on End Turn or
  on the clock. One coach line fixes it.

### Lobby and Create Game

- Lobby shows the roster, Invite and Kick, but not the game's settings. Add a settings card.
- "Thinking" status pills in a lobby are meaningless; use "Joined".
- Create Game has no description of Reverse Attack Order / Non-Random Attacks / Minimum Army
  Bonus beyond one line; link each to the manual section.
- Training Mode should grey out Max Players and Private.

### Tournaments

- Join and Quit are GET links that leave the user on `/Tournament-2/Join`; a refresh re-joins.
  Make them POST forms; the Join/Quit/START/KILL block should be buttons with confirm on KILL.
- The page has no chrome and a light card on a dark theme; the bracket is readable.
- Admin "Create a Tournament" and "Site Stats" links appear on Home only for admins; put them
  in the nav.
